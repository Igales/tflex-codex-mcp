# Развёртывание инструмента «Perplexity ↔ T-FLEX CAD» на другом ПК

Инструкция повторяет схему, которую мы собрали и использовали в этом проекте: Perplexity вызывает инструменты T-FLEX CAD через удалённый MCP-коннектор, а на ПК работает мост-плагин внутри T-FLEX. Документ делится на три части: развёртывание (разделы 1–7), приёмка (раздел 8) и правила работы по моделированию (раздел 9). Эти три задачи не смешиваются.

## 1. Что получится

```
Perplexity (удалённый MCP-коннектор, Streamable HTTP, API Key)
   -> https://<ваш-домен>.ngrok-free.dev/mcp     (ngrok)
   -> SuperGateway 127.0.0.1:8765                (проверка ключа, белый список инструментов)
   -> node mcp\server.js                         (MCP-сервер по stdio)
   -> http://127.0.0.1:38517/command             (HTTP-мост внутри T-FLEX)
   -> активный документ T-FLEX CAD
```

Результат работы: по текстовому описанию или Blender-скрипту ИИ читает API и состояние документа, строит параметрическую модель в открытом документе T-FLEX CAD (переменные, эскизы, выталкивания, булевы операции), пересчитывает и проверяет её по геометрии. Сохранение и экспорт выполняются только по явной просьбе.

## 2. Что нужно подготовить

| Что | Требование |
| --- | --- |
| ОС | Windows, учётная запись с правом записи в каталог T-FLEX (или права администратора) |
| T-FLEX CAD | 17-й версии; проверено на 17.1.55 |
| Сборка плагина | Visual Studio или Build Tools с поддержкой .NET Framework 4.7.2; либо готовый релиз `tflex-codex-mcp-release.zip` |
| Node.js | 18 или новее; проверено на v24.16.0 |
| ngrok | версия 3.39.13 или новее; старая 3.3.1 отклонялась аккаунтом с ошибкой ERR_NGROK_121 |
| Аккаунт ngrok | с настроенным authtoken (`ngrok config add-authtoken ...`) |
| Perplexity | доступ к настройке пользовательских MCP-коннекторов |
| Git | для клонирования форка |
| Рабочая папка | например `D:\dev\TFlex\Test`: только копии файлов, рабочие файлы T-FLEX не открывать |

## 3. Установка проекта

1. Склонируйте форк:
   ```powershell
   cd $HOME\Documents\GitHub
   git clone https://github.com/Igales/tflex-codex-mcp.git
   cd tflex-codex-mcp
   ```
   Состояние, с которым работал этот чат: полный набор из 25 инструментов в `Start-TFlexMcp.cmd`, коммит `f72258abb98fb885b3bc466405de406b678c7476`. Если нужен именно он: `git checkout f72258a`.
2. Установите плагин-мост, один из двух способов.
   - **Готовый релиз.** Скачайте `tflex-codex-mcp-release.zip` со страницы GitHub Releases исходного проекта `Faserdka/tflex-codex-mcp`, распакуйте, откройте PowerShell от имени администратора (если T-FLEX в `Program Files`) и выполните `.\install-tflex-plugin.ps1`.
   - **Сборка из исходников.** В папке проекта:
     ```powershell
     msbuild bridge\TflexCodexBridge.csproj /p:Configuration=Release
     # нестандартный путь T-FLEX:
     msbuild bridge\TflexCodexBridge.csproj /p:Configuration=Release /p:TflexCadDir="D:\Apps\T-FLEX CAD 17\Program"
     .\install-tflex-plugin.ps1
     # или с путём:
     .\install-tflex-plugin.ps1 -TflexRoot "D:\Apps\T-FLEX CAD 17"
     ```
   Установщик копирует плагин в каталог T-FLEX и прописывает «Codex MCP Bridge» в `applications.ini`.
3. Запустите T-FLEX CAD. Плагин стартует сам и слушает `http://127.0.0.1:38517/command`.
4. Проверьте мост:
   ```powershell
   Invoke-RestMethod -Method Post -Uri http://127.0.0.1:38517/command -ContentType 'application/json' -Body '{"command":"ping","args":{}}'
   ```
   Ожидаемый ответ: `ok: true`, сообщение «T-FLEX bridge is running».
5. Проверьте Node.js и ngrok: `node -v`, `npx -v`, `ngrok version`.

## 4. Запуск окружения лаунчером

В корне форка лежит `Start-TFlexMcp.cmd`. Он запускает всё одним файлом. Порядок:

1. Проверяет `node`, `npx`, `ngrok`, `mcp\server.js` и работу моста T-FLEX.
2. Останавливается, если порт 8765 занят. Существующие процессы не завершает. (Порт 8000 давал ошибку EACCES, поэтому выбран 8765.)
3. Если нет файла ключа `%APPDATA%\TFlexMcp\mcp-api-key.dpapi`, создаёт новый (40 символов, шифрование DPAPI под текущего пользователя Windows) и копирует его в буфер обмена. На экран ключ не выводится.
4. Запускает SuperGateway в отдельном окне. Ключ передаётся переменной `SUPERGATEWAY_API_KEY`. Шлюз привязан только к 127.0.0.1.
5. Проверяет: запрос без ключа даёт 401 или 403, запрос с ключом показывает ровно столько инструментов, сколько указано в `$Tools`.
6. Запускает `ngrok http 8765` или переиспользует уже запущенный проверенный туннель, затем проверяет публичный адрес.

Запуск: сначала откройте T-FLEX CAD с плагином, затем запустите `.cmd`. Окна шлюза и ngrok не закрывайте, останавливайте через Ctrl+C. Туннель и шлюз держите включёнными только на время работы.

## 5. Выбор набора инструментов (важно для безопасности)

В начале PowerShell-части лаунчера задан массив `$Tools`. В версии, на которой мы работали, открыты все 25 инструментов:

- мост и документ: `tflex_bridge_ping`, `tflex_bridge_call`, `tflex_active_document`, `tflex_open_document`, `tflex_launch`;
- переменные и пересчёт: `tflex_list_variables`, `tflex_set_variable`, `tflex_create_variable`, `tflex_rebuild`;
- сохранение: `tflex_save`, `tflex_save_as`, `tflex_export`;
- код и документация: `tflex_execute_csharp`, `tflex_docs`;
- модель: `tflex_query_model`, `tflex_create_lcs`, `tflex_model_operation`, `tflex_fragment`, `tflex_mate`;
- рабочий стол: `gui_list_windows`, `gui_focus_window`, `gui_screenshot_window`, `gui_click`, `gui_hotkey`, `gui_type_text`.

Риски исходного проекта (из нашего анализа): у моста нет аутентификации; `tflex_execute_csharp` выполняет произвольный C# внутри T-FLEX без песочницы; `tflex_bridge_call` пропускает любую сырую команду; пути в `open_document`, `save_as`, `export` не проверяются; `gui_*` управляют всем рабочим столом; `tflex_launch` принимает произвольный `exePath`. Через интернет всё это доступно по одному API-ключу.

Рекомендации:
- Для чтения достаточно трёх инструментов: `tflex_bridge_ping`, `tflex_active_document`, `tflex_list_variables`. Начните с них и расширяйте набор поэтапно.
- Для построения по нашему процессу нужны минимум `tflex_active_document`, `tflex_query_model`, `tflex_docs`, `tflex_execute_csharp`, `tflex_rebuild`, `tflex_list_variables`, `tflex_open_document`.
- Инструменты `gui_*`, `tflex_bridge_call`, `tflex_launch`, `tflex_save`, `tflex_save_as`, `tflex_export` включайте только если они действительно нужны, и на время работы.
- Ключ показывайте только в поле API Key коннектора. При подозрении на утечку удалите `%APPDATA%\TFlexMcp\mcp-api-key.dpapi` и запустите лаунчер заново.

## 6. Подключение в Perplexity

1. Plugins → Add custom → Add MCP connector → Remote.
2. Адрес: публичный адрес из вывода лаунчера, с суффиксом `/mcp` (пример: `https://<домен>.ngrok-free.dev/mcp`).
3. Транспорт: Streamable HTTP. Авторизация: API Key. Вставьте ключ из буфера обмена.
4. Чтобы вызвать коннектор в запросе, упоминайте его: `@T-FLEX CAD`.
5. Проверьте вызовами: `tflex_bridge_ping`, затем `tflex_active_document` и `tflex_list_variables`.

Особенности второго ПК:
- Ключ DPAPI привязан к пользователю Windows и машине. На новом ПК лаунчер создаст другой ключ, обновите его в коннекторе или заведите отдельный коннектор.
- Бесплатный домен ngrok закреплён за аккаунтом. Одновременно два ПК на одном домене работать не могут. Если нужны оба, используйте разные аккаунты или платный тариф, и отдельный коннектор на каждое ПК.
- Лимиты и политика бесплатного тарифа ngrok могут меняться.

## 7. Настройка проекта в Perplexity (Space)

Описание проекта, которое мы использовали:

> Создать инструмент управления T-FLEX CAD из диалога с ИИ: по текстовому описанию, чертежу или изображению получать исходник построения и проверенный CAD-документ, а также исследовать и изменять уже открытые документы через плагин внутри CAD. Пользователь запускает CAD и необходимое окружение, задаёт инженерную задачу и получает результат, а не вручную переносит каждый макрос и разбирает ошибки. Инструмент должен сохранять параметрический смысл модели, не подменять CAD-файл картинкой или mesh, выполнять проверки и ясно сообщать степень готовности. Целевой рабочий процесс: описание → чтение API и состояния → план → требуемое согласование → построение/изменение → перестроение и проверки → предусмотренное сохранение → отчёт. Задачи развёртывания, разработки инструмента и обычного моделирования должны быть разделены.

## 8. Приёмка развёртывания

Выполните по порядку и зафиксируйте результат:

| № | Проверка | Ожидание |
| --- | --- | --- |
| 1 | `ping` моста | `ok: true` |
| 2 | Лаунчер | сообщения «T-FLEX bridge: OK», «Gateway check: no key = 401, with key = N tools» (N равно числу инструментов в `$Tools`), публичный адрес с `/mcp` |
| 3 | Публичный запрос без ключа | 401 или 403 |
| 4 | Коннектор в Perplexity | `tflex_bridge_ping` проходит |
| 5 | Чтение документа | `tflex_active_document` возвращает имя; в новом документе 47 штатных переменных, все скрытые и служебные |
| 6 | Проверка записи (только если включены `tflex_execute_csharp` и `tflex_rebuild`) | на тестовой копии в `D:\dev\TFlex` создать переменную, перестроить, прочитать значение |

## 9. Процесс моделирования, как мы его вели

Целевой цикл: описание → чтение API и состояния → план → согласование → построение → перестроение и проверки → отчёт.

1. **Состояние.** Перед любой записью вызвать `tflex_active_document` и `tflex_query_model`. Активный документ не предполагать. Нужен пустой 3D-документ (0 операций), рабочие файлы не трогать.
2. **API.** Читать описание классов через `tflex_docs` (XML-документация в каталоге T-FLEX) и, при необходимости, свойства через рефлексию в `tflex_execute_csharp` без изменений в документе.
3. **План.** Разобрать исходник (чертёж по ЕСКД, Blender-скрипт): параметры с именами и значениями из источника, расчётные размеры отдельно, служебные скрытые; таблица «шаг исходника → операция T-FLEX».
4. **Документ процесса.** Весь процесс описывается одним документом Markdown: разбор, таблица соответствия, параметры, допущения, проверки и код. На выполнение запрашивается одно подтверждение.
5. **Проверка компиляции без изменений.** Перед подтверждением выполнить тот же код с первой строкой
   ```csharp
   if (document != null) return new Dictionary<string, object> { { "dry", "compile-check only" } };
   ```
   Ошибки компиляции видны сразу, документ не меняется.
6. **Построение.** Один вызов `tflex_execute_csharp`. Если скрипт падает на этапе выполнения, изменения откатываются целиком (проверено на муфте: документ остался с 47 штатными переменными).
7. **Перестроение.** `tflex_rebuild` (полное).
8. **Проверки только чтением.** Через C#: число тел, габарит по вершинам, радиусы и оси цилиндрических граней, уровни Z вершин, число граней, значения расчётных переменных. Сравнить с ожиданиями из исходника.
9. **Отчёт.** Что подтверждено числами, чем отличается от исходника, что не проверено (параметричность, `assert` исходника, пересечения тел).
10. **Сохранение и экспорт.** Только по явной просьбе.

## 10. Выученные особенности API (чтобы не наступать повторно)

- Выталкивание `ThickenExtrusion` с `LengthType = AutoValue`: `ForwardLength` и `BackwardLength`. Симметричное выталкивание не зависит от направления нормали.
- Стандартная плоскость Top даёт эскиз с координатами (−X, −Y): для нужного положения координаты эскиза берутся с обратным знаком. Плоскость «Вид слева» даёт (Y, Z) без инверсии.
- Для повернутых плоскостей надёжен приём: локальная система координат по трём параметрическим точкам (`CoordinateNode3D`, `PointsLCS`) и `LCSWorkplane`, а фигура строится центрально-симметричной вокруг начала системы. Тогда ориентация осей плоскости не влияет на результат.
- Булевы операции: `BooleanOperation` с `FirstOperands` и `SecondOperands`, функции `Unite`, `Subtract`, `Intersect`. Тело с переменным сечением получается пересечением двух призм.
- Имена переменных не должны совпадать, и регистр в них, вероятно, не различается: используйте разные имена, не только по регистру. Автогенерируемые имена должны иметь префикс, которого нет у ручных (на муфте `g_p1` совпало и сорвало запуск).
- Тригонометрия в выражениях работает в градусах: `cos(60)`, `sin(180/N)`.
- `ErrorState` у переменных ненадёжен (у всех `true` при пустой `ErrorString`), `Regenerate3D()` из скрипта возвращает `False`, `ApplyChanges` не даёт геометрии внутри запуска. Геометрию читать только после `tflex_rebuild` отдельным вызовом.
- Операции, использованные как операнды булевых, не имеют собственных тел. Читать нужно итоговую операцию.
- Вершинный габарит занижает размеры у цилиндрических граней без вершин на крайней точке: радиусы проверять по граням.
- Один вызов `tflex_execute_csharp` ограничен по времени. Проверено: около 1100 переменных и 60 рабочих плоскостей выполняются нормально.

## 11. Типичные неполадки

| Симптом | Причина и решение |
| --- | --- |
| Лаунчер: «T-FLEX bridge is not reachable» | T-FLEX не запущен или плагин не установлен. Запустите T-FLEX, повторите установку плагина |
| Установщик не пишет в `Program Files` | Запустите PowerShell от администратора или установите в каталог с правом записи |
| «Port 8765 is busy» | Шлюз уже запущен. Лаунчер ничего не завершает: закройте старое окно сами |
| ERR_NGROK_121 | Старый агент ngrok. Обновите до 3.39.13 или новее |
| EACCES на порту | Выбран порт, занятый системой. Используйте 8765 |
| `ConvertTo-SecureString` падает на файле ключа | Перевод строки в файле. В лаунчере уже стоит `.Trim()` |
| «Gateway exposes N tools, expected M» | Расхождение с `$Tools`: проверьте список и перезапустите шлюз |
| В Perplexity «No active T-FLEX document» | В T-FLEX нет открытого документа. Откройте пустой 3D-документ |
| Ошибка компиляции в `tflex_execute_csharp` | Смотрите строку и номер ошибки CS в ответе; документ не менялся |
| Ошибка выполнения | Изменения откатились. Исправьте причину и запросите подтверждение заново |

## 12. Правила безопасности

- Рабочие файлы T-FLEX не открывать, только копии в тестовой папке.
- Ключ и адрес туннеля не публиковать.
- Туннель и шлюз держать включёнными только на время работы.
- Выполнение C# и `gui_*` через интернет включать только осознанно, на время сеанса.
- Сохранение, экспорт и запись вне тестовой папки только по явной просьбе.

## 13. Следующие шаги для усиления (по итогам нашего анализа)

1. Токен для моста (аутентификация на стороне `BridgeServer.cs`).
2. Защита путей для `save_as` и `export`: запись только внутри `D:\dev\TFlex`.
3. Автоматическая сборка отчёта о готовности после перестроения (число тел, габарит, расчётные размеры) прямо в инструменте.
4. Проверка параметричности: изменение ключевых параметров и повторные проверки геометрии.
5. Режим выполнения C# только локально и с явным подтверждением.
