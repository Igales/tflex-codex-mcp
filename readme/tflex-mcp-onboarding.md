# T-FLEX CAD + Perplexity: удалённый MCP-коннектор. Статус, развёртывание и работа

Дата: 23.11.2026. Владелец: Игорь Санников. Статус: рабочий инструмент. Чтение, параметрическое построение и пересчёт проверены на реальных деталях (раздел 11). Сохранение и экспорт по умолчанию не используются.

Документ объединяет прежние «введение в курс дела» и «инструкцию по развёртыванию на другом ПК». Развёртывание (разделы 4–8), приёмка (раздел 9) и работа по моделированию (разделы 3, 10, 12) разделены намеренно.

## 1. Цель

Управлять T-FLEX CAD из диалога в Perplexity: по текстовому описанию, чертежу или изображению получать исходник построения и проверенный CAD-документ, а также исследовать и изменять уже открытые документы через плагин внутри CAD.

Требования проекта: сохранять параметрический смысл модели, не подменять CAD-файл картинкой или mesh, выполнять проверки, ясно сообщать степень готовности. Целевой процесс: описание → чтение API и состояния → план → требуемое согласование → построение/изменение → перестроение и проверки → предусмотренное сохранение → отчёт.

## 2. Архитектура

```
Perplexity (удалённый MCP-коннектор, Streamable HTTP, API Key)
   -> https://<ваш-домен>.ngrok-free.dev/mcp   (ngrok)
   -> SuperGateway 127.0.0.1:8765               (проверка ключа, белый список инструментов)
   -> node mcp\server.js                        (MCP-сервер по stdio)
   -> http://127.0.0.1:38517/command            (HTTP-мост внутри T-FLEX)
   -> активный документ T-FLEX CAD
```

| Параметр | Значение |
| --- | --- |
| Порт шлюза | 8765 (порт 8000 давал ошибку EACCES) |
| Привязка шлюза | только 127.0.0.1 |
| Авторизация | API Key: `Authorization: Bearer` или `X-API-Key` |
| Хранение ключа | `%APPDATA%\TFlexMcp\mcp-api-key.dpapi` (DPAPI, учётная запись Windows) |
| Тестовая папка | `D:\dev\TFlex` (путь можно заменить) |
| Проверено на | T-FLEX CAD 17.1.55, Node.js v24.16.0, ngrok 3.39.13 |

Форк: `Igales/tflex-codex-mcp` (исходный проект `Faserdka/tflex-codex-mcp`, MIT). Состояние, с которым собраны примеры ниже: коммит `f72258a` (в лаунчере открыт полный набор из 25 инструментов).

## 5. Установка

1. Клонирование:
   ```powershell
   git clone https://github.com/Igales/tflex-codex-mcp.git
   cd tflex-codex-mcp
   ```
2. Плагин-мост, один из двух способов.
   - Готовый релиз: распаковать `tflex-codex-mcp-release.zip`, открыть PowerShell от администратора (если T-FLEX в `Program Files`), выполнить `.\install-tflex-plugin.ps1`.
   - Сборка из исходников:
     ```powershell
     msbuild bridge\TflexCodexBridge.csproj /p:Configuration=Release
     # нестандартный путь T-FLEX:
     msbuild bridge\TflexCodexBridge.csproj /p:Configuration=Release /p:TflexCadDir="D:\Apps\T-FLEX CAD 17\Program"
     .\install-tflex-plugin.ps1                                  # или: -TflexRoot "D:\Apps\T-FLEX CAD 17"
     ```
   Установщик копирует плагин в каталог T-FLEX и прописывает «Codex MCP Bridge» в `applications.ini`.
3. Запустить T-FLEX CAD. Плагин стартует сам и слушает `http://127.0.0.1:38517/command`.
4. Проверить мост:
   ```powershell
   Invoke-RestMethod -Method Post -Uri http://127.0.0.1:38517/command -ContentType 'application/json' -Body '{"command":"ping","args":{}}'
   ```
   Ожидается `ok: true`, «T-FLEX bridge is running».
5. Проверить `node -v`, `npx -v`, `ngrok version`.

## 6. Лаунчер `Start-TFlexMcp.cmd`

Лежит в корне форка. Порядок:

1. Проверяет `node`, `npx`, `ngrok`, `mcp\server.js` и работу моста T-FLEX.
2. Останавливается, если порт 8765 занят. Существующие процессы не завершает.
3. Если нет файла ключа, создаёт новый (40 символов, DPAPI под текущего пользователя) и копирует в буфер обмена. На экран ключ не выводится.
4. Запускает SuperGateway в отдельном окне, ключ передаётся переменной `SUPERGATEWAY_API_KEY`.
5. Проверяет: без ключа 401 или 403, с ключом ровно столько инструментов, сколько в `$Tools`.
6. Запускает `ngrok http 8765` или переиспользует проверенный туннель, затем проверяет публичный адрес.

Запуск: сначала T-FLEX с плагином, затем `.cmd`. Окна шлюза и ngrok не закрывать, останавливать через Ctrl+C. Ключ читается с `.Trim()` (иначе перевод строки ломал `ConvertTo-SecureString`).

## 7. Набор инструментов и безопасность

Список инструментов задаётся массивом `$Tools` в начале PowerShell-части лаунчера. Рекомендуемые профили:

| Профиль | Инструменты |
| --- | --- |
| Чтение (безопасное начало) | `tflex_bridge_ping`, `tflex_active_document`, `tflex_list_variables` |
| Построение (то, что нужно для раздела 10) | профиль «Чтение» + `tflex_query_model`, `tflex_docs`, `tflex_open_document`, `tflex_rebuild`, `tflex_execute_csharp` |
| Полный (25) | всё, включая `tflex_bridge_call`, `tflex_launch`, `tflex_save`, `tflex_save_as`, `tflex_export`, `gui_*`, `tflex_fragment`, `tflex_mate`, `tflex_model_operation`, `tflex_create_lcs`, `tflex_set_variable`, `tflex_create_variable` |

Сильные стороны исходного проекта: мост привязан к localhost, один маршрут `POST /command`, лимит тела 5 МБ, защита от запросов из браузера (Origin, Host, Content-Type), правки идут через `BeginChanges`/`EndChanges` с откатом, `save` по умолчанию выключен.

Риски: у моста нет аутентификации; `tflex_execute_csharp` выполняет произвольный C# внутри T-FLEX без песочницы; `tflex_bridge_call` пропускает любую сырую команду; пути в `open_document`, `save_as`, `export`, `execute_csharp` не проверяются; `gui_*` управляют всем рабочим столом; `tflex_launch` принимает произвольный `exePath`. В полном профиле всё это доступно через интернет по одному API-ключу. Включайте профиль «Построение» на время сеанса, остальное только по необходимости.

Правила:
- Рабочие файлы T-FLEX не открывать, только копии в тестовой папке.
- Ключ показывать только в поле API Key коннектора. При подозрении на утечку удалить файл ключа и запустить лаунчер заново.
- Туннель и шлюз держать включёнными только на время работы.
- Сохранение, экспорт и запись вне тестовой папки только по явной просьбе.

## 8. Подключение в Perplexity

1. Plugins → Add custom → Add MCP connector → Remote.
2. Адрес: публичный адрес из вывода лаунчера с суффиксом `/mcp`. Транспорт Streamable HTTP, авторизация API Key (ключ из буфера обмена).
3. Вызов коннектора в запросе: `@T-FLEX CAD`.
4. Проверка: `tflex_bridge_ping`, затем `tflex_active_document` и `tflex_list_variables`.

Второй ПК: ключ DPAPI привязан к пользователю Windows, на новом ПК лаунчер создаст другой ключ, его нужно внести в коннектор или завести отдельный коннектор. Бесплатный домен ngrok закреплён за аккаунтом и не может обслуживать два ПК одновременно.

Описание проекта (Space), которое задаёт поведение:

> Создать инструмент управления T-FLEX CAD из диалога с ИИ: по текстовому описанию, чертежу или изображению получать исходник построения и проверенный CAD-документ, а также исследовать и изменять уже открытые документы через плагин внутри CAD. Пользователь запускает CAD и необходимое окружение, задаёт инженерную задачу и получает результат, а не вручную переносит каждый макрос и разбирает ошибки. Инструмент должен сохранять параметрический смысл модели, не подменять CAD-файл картинкой или mesh, выполнять проверки и ясно сообщать степень готовности. Целевой рабочий процесс: описание → чтение API и состояния → план → требуемое согласование → построение/изменение → перестроение и проверки → предусмотренное сохранение → отчёт. Задачи развёртывания, разработки инструмента и обычного моделирования должны быть разделены.

## 10. Как ставить задачу и как идёт работа

Процесс (так вёлся весь эксперимент):

1. **Состояние.** Перед записью `tflex_active_document` и `tflex_query_model`. Нужен пустой 3D-документ (0 операций). Активный документ не предполагать.
2. **API.** Описание классов через `tflex_docs`, свойства через рефлексию в `tflex_execute_csharp` без изменений в документе.
3. **План.** Параметры с именами и значениями из источника, расчётные размеры отдельно, служебные скрытые; таблица «шаг исходника → операция T-FLEX».
4. **Документ процесса.** Один документ Markdown: разбор, таблица, параметры, допущения, проверки и код. На выполнение один запрос подтверждения.
5. **Проверка компиляции без изменений.** Тот же код с первой строкой
   ```csharp
   if (document != null) return new Dictionary<string, object> { { "dry", "compile-check only" } };
   ```
6. **Построение.** Один вызов `tflex_execute_csharp`. При ошибке выполнения изменения откатываются целиком.
7. **Перестроение.** `tflex_rebuild` (полное).
8. **Проверки только чтением.** Число тел, габарит, радиусы и оси цилиндрических граней, уровни Z вершин, число граней, значения расчётных переменных.
9. **Отчёт.** Что подтверждено числами, чем отличается от источника, что не проверено.
10. **Сохранение и экспорт.** Только по явной просьбе.

### Пример промта: модель из Blender-скрипта

```text
@T-FLEX CAD Я открыл новый пустой 3D-документ. Прикрепляю Python-скрипт для Blender
со стенами параметрических деталей. Разбери построение детали «01_Pole_socket» и реализуй её в T-FLEX.

Условия:
1. Параметры возьми из скрипта: имена и значения как в Blender, расчётные размеры отдельной группой,
   служебные переменные скрытые.
2. Модель должна быть параметрической: эскизы, выталкивание и булевы операции, никаких mesh и картинок.
3. Сначала проверь активный документ (должен быть пустой) и API через tflex_docs.
4. Весь процесс опиши одним документом: разбор построения, таблица «шаг скрипта → операция T-FLEX»,
   параметры, допущения, проверки и исполняемый код. Проверь компиляцию без изменений в документе.
5. Запроси ОДНО подтверждение на создание. После него выполни построение, полное перестроение
   и проверки геометрии только чтением (число тел, габарит, радиусы и оси отверстий, расчётные размеры).
6. Ничего не сохраняй и не экспортируй.
7. В отчёте перечисли: что подтверждено числами, чем отличается от скрипта, что не проверено.
```

### Пример промта: модель по чертежу ЕСКД

```text
@T-FLEX CAD Прикрепляю чертёж детали. Прочти его по требованиям ЕСКД, выпиши все проставленные размеры
с обозначениями и значениями и сначала покажи мне этот список.
Затем построй параметрическую 3D-модель в открытом пустом документе T-FLEX CAD:
- параметрами сделай только размеры, явно проставленные на чертеже; не добавляй параметры
  для непроставленных размеров и допущений;
- не заменяй модель картинкой или mesh;
- весь процесс опиши одним исполняемым документом с одним подтверждением на создание;
- после построения выполни перестроение и проверь геометрию (габарит, число и размеры отверстий)
  и сообщи степень готовности. Ничего не сохраняй.
```

## 11. Результаты эксперимента (23.11.2026)

Первый эксперимент: пластина по чертежу ЕСКД с 17 параметрами, пересчёт и проверка геометрии (число и радиусы отверстий, габарит).

Второй эксперимент: детали из Blender-скрипта «Skimmer mount / Ice stop», каждая одним документом и одним подтверждением.

| Деталь | Параметров | Подтверждено проверкой | Отличия от скрипта |
| --- | --- | --- | --- |
| `01_Pole_socket` | 31 | 1 тело, ширина приёмника ±18,05; оси отверстий и ласточкин хвост на своих местах | нет |
| `02_Reinforced_sensor_adapter` | 25 | 1 тело; уши на 10,05…18,05, R12 вырез, отверстия M6 и штифта | порядок построения ушей иной, результат тот же |
| `03_Left_serrated_insert` (одна из двух одинаковых) | 8 | 24 отдельных гребня, без врезов в основание | плоские грани зубьев, вертикальные стенки зоны зубьев, только профиль TRIANGLE |

Не проверялись: параметричность (смена значений и повторные проверки), `assert` исходного скрипта, пересечения тел между деталями. Документы не сохранялись.

## 12. Выученные особенности API

- `ThickenExtrusion` с `LengthType = AutoValue`: `ForwardLength` и `BackwardLength`. Симметричное выталкивание не зависит от направления нормали.
- Плоскость Top даёт эскиз с координатами (−X, −Y), плоскость «Вид слева» (Y, Z) без инверсии.
- Для повёрнутых плоскостей: ЛСК по трём параметрическим точкам (`CoordinateNode3D`, `PointsLCS`) и `LCSWorkplane`; фигуры строить центрально-симметричными вокруг начала, тогда ориентация осей плоскости не влияет на результат.
- Булевы: `BooleanOperation` с `FirstOperands`, `SecondOperands`, функции `Unite`, `Subtract`, `Intersect`. Тело с переменным сечением получается пересечением двух призм.
- Имена переменных должны быть уникальны (регистр, вероятно, не различается); автоимена должны иметь префикс, которого нет у ручных (на муфте конфликт `g_p1` сорвал запуск, документ откатился).
- Тригонометрия в выражениях в градусах.
- `ErrorState` у переменных ненадёжен, `Regenerate3D()` из скрипта возвращает `False`, `ApplyChanges` не даёт геометрии внутри запуска: геометрию читать после `tflex_rebuild` отдельным вызовом.
- У операций-операндов булевых нет собственных тел: читать итоговую операцию.
- Вершинный габарит занижает размеры у цилиндрических граней: радиусы проверять по граням.
- Один вызов `tflex_execute_csharp` ограничен по времени: около 1100 переменных и 60 рабочих плоскостей выполнились нормально.

## 13. Типичные неполадки

| Симптом | Причина и решение |
| --- | --- |
| «T-FLEX bridge is not reachable» | T-FLEX не запущен или плагин не установлен |
| Установщик не пишет в `Program Files` | PowerShell от администратора или каталог с правом записи |
| «Port 8765 is busy» | Шлюз уже запущен; лаунчер ничего не завершает, закройте старое окно |
| ERR_NGROK_121 | Обновить ngrok до 3.39.13 или новее |
| EACCES на порту | Использовать порт 8765 |
| «Gateway exposes N tools, expected M» | Проверить `$Tools`, перезапустить шлюз |
| «No active T-FLEX document» | Открыть пустой 3D-документ |
| Ошибка компиляции в `tflex_execute_csharp` | Смотреть строку и номер CS-ошибки; документ не менялся |
| Ошибка выполнения | Изменения откатились; исправить причину и запросить подтверждение заново |

## 15. Ограничения и открытые вопросы

- Чтение структуры модели ограничено возможностями `tflex_query_model` и C#-проверок; полный граф зависимостей не выгружался.
- Имя заголовка с API-ключом, который шлёт Perplexity, не выясняли: шлюз принимает оба варианта.
- Лимиты и политика бесплатного ngrok могут меняться.
- Проверка проводилась на T-FLEX 17.1.55; установка с нуля на чистой машине по этому документу ещё не выполнялась.

## 16. Глоссарий

- MCP: Model Context Protocol, протокол подключения инструментов к ИИ.
- Мост: управляемый плагин внутри T-FLEX с HTTP-сервером на localhost.
- Шлюз: SuperGateway, превращает stdio-сервер в HTTP-эндпоинт.
- Белый список: флаги `--tools` шлюза, оставляющие только перечисленные инструменты.
- DPAPI: шифрование Windows, привязанное к учётной записи.
- ЛСК: локальная система координат.
